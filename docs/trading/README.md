# 트레이딩 시스템 문서

## 대전제 (사용자 제시)

1. 전종목을 평가하고 다음날 승률을 올릴 수 있는 종목을 발굴하여 수익을 얻는다.
2. **특히 하락장에서 수익을 내는 것을 최우선으로 한다** (2026-08-03 갱신).
   현물 계좌라 개별주 공매도는 불가 — 하락 수익 수단은 인버스 ETF 매수와
   하락장에서의 손실 억제(롱 노출 제어)다. 모든 계획·측정의 우선순위는 이
   전제 위에서 선다.

반자동 한국주식 트레이딩 시스템(키움증권 REST/WS · 실계좌)의 문서 세트.
개선 작업을 시작하기 전에 **해당 영역 문서를 먼저 읽는 것**을 전제로 쓰였다 —
이 시스템은 "구현 → 측정 → 유지/폐기" 사이클로 발전해 왔고, 지금 코드에 없는
것들 상당수는 **측정으로 폐기된 것**이라 다시 만들면 같은 대가를 치른다.

## 30초 요약

```
[발굴]  6개 소스 → 신호 원장(scout.db) → 취합 점수 → 게이트 승격 → 감시목록 (단일 통로)
[매매]  감시목록(매매 tier) → 규칙 평가(60초) → 게이트 체인 → 승인대기 → 사용자 승인 → 발주
[청산]  매매 데스크(2초, WS 가격) → 손절 자동 / 목표 승인제
[검증]  결정·관측 원장 축적 → 사전 확정된 기준으로 사후 판정 → 유지/폐기
```

핵심 설계 원칙 세 가지:

1. **단일 통로** — 감시목록에 쓰는 주체는 발굴 엔진(+수동)뿐이다. 과거 5갈래
   직접 편입이 만든 결함(귀속 오염·전량 교체 진동·게이트 우회)은 전부 실측됐고,
   그 경로들은 폐기됐다(부활 방지 테스트 있음).
2. **점수는 예측이 아니다** — 어떤 랭킹도 매수가능 무작위를 못 이긴다는 것이
   실측됐다(191거래일). 점수의 용도는 강등 순서와 화면 표시뿐이고, 매매 승격은
   유동성·체결가능성·probation·상한 **게이트**로만 결정한다.
3. **측정 없이 정하지 않는다** — 새 기능은 관측 전용으로 들어와 원장을 쌓고,
   사전에 못박은 기준으로 4주 뒤 판정한다. 기준을 결과 본 뒤 바꾸면 그 측정은
   버린다. → [measurement.md](measurement.md)
