# 트레이딩 시스템 컨벤션 가드

이 저장소는 **실계좌**가 걸린 시스템이고, 지금의 구조는 실측·실사고로 값을 치르고
얻은 것이다. 아래 불변 조건들은 취향이 아니라 사고 재발 방지 장치다 — 어기는
코드는 리뷰에서가 아니라 장중에 발견된다.

## 시작 전 3분 — 반드시 읽을 것

1. `docs/trading/README.md` — 문서 지도. 처음이면 architecture.md 까지
2. **무언가를 바꾸기 전에 `docs/trading/measurement.md`** — 지금 코드에 없는 것
   상당수는 측정으로 **폐기된 것**이다. 다시 만들면 같은 대가를 치른다
3. 작업 유형별 레시피(아래 라우터)를 골라 그 문서를 따라간다

## 불변 조건 — 어떤 작업에서도 깨면 안 되는 것

1. **감시목록 쓰기는 단일 통로** — 발굴 엔진(scout) apply 와 수동 조작뿐이다.
   `replace_*` 류 직접 편입을 되살리지 않는다(부활 방지 테스트가 있다:
   `test_nightly_absorption.py`). 새 기능이 감시목록을 바꾸고 싶으면 **신호를
   엔진에 올리는 소스**로 만든다.
2. **점수는 예측이 아니다** — 매매 tier 승격은 게이트(유동성·체결가능성·
   probation·상한)로만. 점수 임계로 매매를 여는 코드를 넣지 않는다(랭킹이
   무작위를 못 이긴다는 191거래일 실측이 근거).
3. **신호는 전부 기록, 발주만 게이트** — 차단하더라도 signal_log 에 사유(note)와
   함께 남긴다. 조용히 사라지는 신호는 사후 검증을 불가능하게 만든다.
4. **새 기능은 관측 전용으로 들어온다** — 신호·점수·주문에 넣지 않고 원장부터
   쌓는다. 판정 질문과 기준을 **구현 시점에 docstring 으로 못박는다**(결과를
   본 뒤 기준을 바꾸면 그 측정은 버린다).
5. **실거래 사실의 원본은 증권사다** — 손익·체결·수량은 broker_fills/broker_daily
   (trade/fills.py) 기준. 시스템 positions 는 의도(손절·목표·규칙 귀속) 레이어다.
   모델 비용으로 새 손익 계산을 만들지 않는다.
6. **데이터 연속성 불변** — `discovery.db` 파일명, 표본 시드 문자열
   `{day}:discovery`/`{day}:screen`, 관측 원장 스키마의 기존 컬럼 의미를 바꾸지
   않는다. 과거 표본과의 비교 가능성이 걸려 있다.
7. **config 와 코드 DEFAULTS 는 동기** — 같은 키가 양쪽에 있으면 값을 맞춘다
   (드리프트가 운영/테스트 불일치 버그를 만든 전례: 진단 2026-08-01 M6).
8. **API 예산은 전 루프 공유 단일 자원** — 새 REST 호출을 늘리는 기능은 분당
   콜 수를 계산해 커밋 메시지에 남기고, 가능하면 이미 지불한 데이터(WS 틱·
   저장 봉·기존 응답의 미사용 필드)를 재사용한다.
9. **되돌릴 수 있게** — 실거래에 닿는 새 동작은 config/런타임 오버라이드
   (`data/*.json`)로 배포 없이 끌 수 있어야 하고, 기본값은 보수적인 쪽이다.

## 작업 유형 라우터

| 하려는 일 | 레시피 |
|---|---|
| 새 매매 규칙(기법) 추가·수정, 규칙 파라미터/시간창 | `references/new-rule.md` |
| 발굴 소스·관측 수집기 추가, scout 엔진·게이트 수정 | `references/new-source.md` |
| API 엔드포인트·화면 카드 추가, 배선 누락 방지 | `references/wiring.md` |
| 측정 결과를 코드에 반영, 새 측정 도구 | `references/measurement-flow.md` |
| 커밋·PR·배포·검증 | `references/ship.md` |

레시피는 짧다 — 해당 파일 하나만 읽으면 된다. 두 유형에 걸치면 둘 다 읽는다.

**"무엇을 할지"가 아직 정해지지 않았다면**(우선순위·아이디어 평가·로드맵)
`trading-planner` 스킬이 먼저다 — 이 스킬은 정해진 일을 어떻게 구현하는지만
다룬다.

## 코드 스타일 — 이 저장소의 목소리

- 주석·docstring·테스트 이름은 **한국어**. 주석은 "무엇"이 아니라 **왜** — 특히
  값·설계의 **근거를 실측 날짜와 함께** 적는다
  (예: `# 실측 2026-07-31: 보유 2종목에 분당 47콜`). 근거 없는 매직넘버 금지.
- 폐기·수정된 동작의 주석은 **경위를 남긴다** — "왜 이렇게 안 하는가"가 다음
  사람이 같은 실수를 반복하지 않게 하는 장치다.
- 예외 격리: 한 종목/한 소스의 실패가 루프 전체를 멈추지 않게
  (`except Exception: log...; continue` + `# noqa: BLE001` 사유 주석).
- 못 잰 것을 0으로 세지 않는다 — NULL 은 NULL 로 남기고 표본에서 뺀다.
- 시각은 KST(`ZoneInfo("Asia/Seoul")`), 날짜 문자열은 ISO. naive 값은 KST 로 해석.

## 테스트 규약

- 실 DB·네트워크 없이 monkeypatch (`DB_PATH`/`STATE_FILE`/`settings.CONFIG` 를
  tmp_path 로). 테스트 이름은 한국어로 **행동을 서술**
  (`test_유령은_체결내역에_없으면_void`).
- 버그 수정에는 회귀 테스트를 함께 — "이 사고가 다시 나면 이 테스트가 잡는다".
- 경계값을 시나리오로: 시간 경계(세션 시작/끝), 빈 표본, 조회 실패(None)의
  보수적 처리.
- 전체 스위트: `cd trading && python -m pytest tests -q`(1,100+) ·
  루트 `python -m pytest tests -q` · tnm 변경 시 `pytest tnm/tests` ·
  JS 변경 시 `node --check static/pages/<파일>.js`. **전부 초록이어야 커밋한다.**

## 하지 않을 것 (측정·사고로 확정된 금지 목록)

- 점수 기반 매매 승격 부활, 소스 가중치 수동 조정·학습 (측정 근거 없음)
- LLM 을 점수·승격·강등·주문 판단에 투입
- 장중(평일 09:00~15:30)·야간 배치(17:30~) 중 배포
- `long_only` 를 끄는 코드/설정 (현물 계좌 — 숏은 인버스 ETF 로만)
- 리스크·자동발주·매매 설정의 임의 변경 — **사용자 결정 사항**
- 30분 넘는 서버 측 작업을 MCP run_command 자식으로 실행
  (`systemd-run` 독립 유닛으로 — MCP 재시작에 죽는다, 실측 2026-08-01 두 번)
